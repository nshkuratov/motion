# Как создать многослойный сайт с кинематографичной анимацией

**Полное практическое руководство · Русский · 30 октября 2026 года**  
[English version](build-guide.en.md) · [Оглавление документации](README.md) · [README проекта](../README.md)

Это руководство объясняет, как воспроизвести MOTION, а затем создать похожий сайт с собственными изображениями. Здесь разобраны подготовка графики, композиция, структура HTML, CSS-анимации, управление скроллом, самостоятельное движение фона, реакция на курсор, мобильная версия, доступность, производительность, проверка и публикация. Предполагается базовое знакомство с HTML, CSS, JavaScript и React; устройство анимации объясняется с самого начала.

**Дополнение от 31 октября:** к описанной CSS-основе добавлено необязательное улучшение через PixiJS. В [двуязычном дополнении](pixi-effects.md) разобраны шейдеры воды и марева, отложенная загрузка, новые контейнеры камер, ограничения нагрузки и очистка. CSS и исходные изображения остаются запасным вариантом.

Файлы исходного кода, на которые ведут ссылки, — **полная работающая реализация**. Фрагменты кода в тексте показывают отдельные механизмы или явно обозначенные примеры. Их не нужно объединять в один файл вместо приложения. Чтобы получить точную копию, выполните раздел 2 и сохраните полный набор исходников. Чтобы создать новый дизайн, проходите разделы последовательно и меняйте по одной системе за раз.

## 1. Что создаём: три независимых источника движения

Страница состоит из обычных HTML-элементов с растровыми изображениями. Впечатление объёма создают прозрачные вырезанные объекты, независимые трансформации, согласованные перекрытия и визуальные признаки глубины. Для этого не обязательны 3D-движок, видеофон или библиотека анимации.

В проекте работают три независимые системы:

| Система | Что получает на входе | Чем управляет | На каком элементе работает |
| --- | --- | --- | --- |
| Прогресс истории от 0 до 1 | Положение прокрутки страницы | Появление и уход сцен, смена фона, передний план, текст | Внешние контейнеры `.motion-layer` |
| Время | Обычная CSS-анимация | Медленное приближение и смещение фона, даже без скролла | Изображения `.world-camera` |
| Координаты курсора от −1 до 1 | Положение мыши внутри сцены | Небольшое смещение и поворот главного объекта | Изображения внутри `.world-object` |

Контроллер навигации за 1,8 секунды изменяет положение прокрутки. CSS считывает это положение и показывает нужную стадию перехода. Фон продолжает собственную анимацию по времени. Курсор воздействует на отдельный вложенный элемент.

```text
Колесо / свайп / клавиатура / кнопка сцены
                      ↓
            общий контроллер навигации
                      ↓
       плавное изменение положения скролла
                      ↓
       нормализованный прогресс истории 0…1
                      ↓
       внешние слои: перемещение и прозрачность

Время  → внутреннее изображение фона: движение камеры
Мышь   → внутреннее изображение объекта: параллакс
```

**Главное правило: разные системы трансформаций должны управлять разными DOM-элементами.** Если две анимации записывают `transform` одному элементу, обычно одна заменяет другую. Вложите изображение в контейнер, который анимируется от скролла: трансформации родителя и ребёнка будут складываться естественным образом.

## 2. Как запустить и воспроизвести проект

### 2.1 Что потребуется

Нужны Node.js и npm. Установленный Vite 7.3.7 указывает требование Node `^20.19.0 || >=22.12.0`; выбирайте поддерживаемую версию Node, которая удовлетворяет этому диапазону. В манифесте проекта указаны React 19, Vite 7 и Sharp для подготовки графики. Для точного воспроизведения используйте lock-файл, а не заменяйте все зависимости на последние версии. У нового шаблона Vite требования могут отличаться; они описаны в [официальном руководстве Vite](https://vite.dev/guide/).

Проверьте окружение:

```sh
node --version
npm --version
```

Для существующего проекта:

```powershell
Set-Location D:\program\motion
npm ci
npm run dev
```

Откройте адрес, который напечатал Vite, обычно `http://127.0.0.1:5173/`. Если порт занят, сервер может выбрать другой. Чтобы требовать именно этот порт, выполните `npm run dev -- --port 5173 --strictPort`. Не открывайте `index.html` двойным щелчком через файловую систему: приложение использует ES-модули и сервер сборщика.

Если lock-файла ещё нет, используйте `npm install` и сохраните созданный lock-файл. Команда `npm ci` требует, чтобы lock-файл существовал и соответствовал `package.json`.

### 2.2 Точная копия в новой папке

Скопируйте в новую папку проекта:

```text
package.json + package-lock.json   зависимости и их зафиксированные версии
index.html                        метаданные и точка входа
src/                              полное приложение
public/                           изображения, шрифты, favicon
scripts/                          подготовка графики и тесты навигации
artwork/                          исходные PNG для повторного экспорта
docs/, PRODUCT.md, DESIGN.md       знания о реализации и дизайне
```

Не переносите `node_modules`, `dist` и журналы сервера. В новой папке выполните `npm ci`, `npm run dev`, затем `npm run build`. Для запуска уже экспортированного сайта исходные PNG не обязательны: браузер использует WebP из `public/images`. PNG нужны для дальнейшего редактирования и повторной конвертации.

### 2.3 За что отвечают файлы

| Файл | Назначение |
| --- | --- |
| [main.jsx](../src/main.jsx) | Запускает React и подключает общие стили |
| [App.jsx](../src/App.jsx) | Активная сцена, настройка уменьшения движения, жизненный цикл навигации, запасной расчёт прогресса, остальные разделы и форма |
| [Worlds.jsx](../src/Worlds.jsx) | Описание трёх сцен, разметка слоёв, реакция на курсор, видимость фоновой анимации |
| [motion.css](../src/motion.css) | Закреплённая сцена, ключевые кадры, траектории фонов, адаптивность и уменьшение движения |
| [sceneNavigation.js](../src/sceneNavigation.js) | Координаты назначения, плавность, фильтрация ввода, throttle, удаление обработчиков |
| [style.css](../src/style.css) | Шрифты, дизайн-переменные, шапка, студия, форма и подвал |
| [prepare-assets.mjs](../scripts/prepare-assets.mjs) | Конвертирует восемь PNG-слоёв в WebP |

В `style.css` также сохранились старые правила `.scene-*`. Текущие кинематографичные сцены используют `.world-*` в `motion.css`. При изменении этих эффектов работайте с актуальной системой.

## 3. Как спланировать визуальную историю

До генерации изображений составьте раскадровку из трёх строк. Для каждой сцены запишите идею, окружение, главный объект, передний план, направление света, основной цвет, текст и направление движения.

| Сцена | Смысл | Окружение | Главный объект | Отдельный передний план |
| --- | --- | --- | --- | --- |
| Cloud nine | Неожиданная идея | Лавандовое небо, персиковые облака, далёкое море | Зеркальное хромированное кольцо | Облачная масса |
| Otherworld | Другой взгляд | Оранжевые дюны и терракотовое небо | Большая луна | В этой реализации отсутствует |
| Afterglow | Впечатление, которое остаётся | Лавандовое море и закат | Перламутровая стеклянная скульптура | Морская волна |

Дюны во второй сцене входят в фоновое изображение; они не являются отдельными анимированными слоями. Разделяйте изображение там, где необходимо независимое движение или перекрытие, а не ради количества элементов.

Сохраняйте общий визуальный язык: персиковые блики, фиолетовые тени, крупные скульптурные формы, свет сверху справа и фотографичную фактуру. У каждой сцены может быть собственная палитра, но общие признаки должны связывать их. Холодный синий объект с освещением с противоположной стороны будет выглядеть вклеенным в оранжевую пустыню даже с идеальной маской.

Примерно левые 40% широкого кадра оставьте относительно спокойными для текста. Главный объект разместите ближе к центру справа. Определите горизонт и масштаб до анимации. Проверяйте макет с настоящим заголовком: без текста композиция может выглядеть удачно, но три строки перекроют её главный акцент.

Сформулируйте постановку движения: «Главный объект поднимается и покидает сцену; следующий появляется снизу. Передний план движется по другой траектории. Фоны перекрываются и растворяются. Строки заголовка расходятся. В состоянии покоя камера медленно смещается». Это уже конкретное задание для реализации.

## 4. Как устроить слои сцены

Разделяйте сцену по глубине, от дальнего к ближнему:

1. **Чистый фон:** полное небо, пейзаж и атмосфера без главного объекта.
2. **Главный объект:** целиком восстановленный объект на прозрачном фоне, которым можно управлять отдельно.
3. **Второстепенный передний план:** облака, пена, растения, туман или другой элемент, который частично перекрывает объект и усиливает глубину.
4. **Затемнение для читаемости:** CSS-градиент за текстом; не рисуйте его в исходном изображении.
5. **Текст:** отдельные строки заголовка, описание и подпись.
6. **Управление:** кнопки и ссылки поверх анимированного окружения.

```text
.worlds-scroll                         высокий контейнер прокрутки
└── .worlds-stage                       закреплённый обрезающий кадр
    ├── .world-backdrops                позади содержимого сцен
    │   └── .world-backdrop.motion-layer     скролл и прозрачность
    │       └── img.world-camera             движение по времени
    ├── section.world
    │   ├── .world-object.motion-layer       движение от скролла
    │   │   └── img                          движение от курсора
    │   ├── .cloud-foreground.motion-layer / .ocean-foreground
    │   ├── .world-scrim.motion-layer
    │   ├── .world-copy → заголовок → .story-line.motion-layer
    │   ├── .world-description.motion-layer
    │   └── .world-caption.motion-layer
    └── .world-navigation
```

Если в исходном кадре нижняя часть объекта скрыта облаками, вырезанный объект всё равно должен иметь полноценный нижний край. Иначе при движении откроется плоский обрезанный участок. У кольца прозрачность нужна не только вокруг внешнего контура, но и в центральном отверстии.

## 5. Как создать и разделить изображения

### 5.1 Два способа подготовки

**Сначала готовая композиция, затем разделение.** Создайте утверждённую сцену целиком, после чего получите из неё чистый фон, объект и передний план. Так проще сохранить согласованные свет и отражения. Но придётся восстановить пиксели, которые изначально были скрыты объектами.

**Сразу отдельные слои по общему заданию.** Генерируйте или рендерите окружение и объект отдельно, используя одинаковые свет, палитру, перспективу и материалы. Способ даёт больше свободы, но требует внимательного сведения, чтобы не было разницы в тенях и масштабе. В MOTION использованы оба подхода; исходные цельные композиции облаков и пустыни также сохранены в `artwork`.

### 5.2 Пошаговое разделение в графическом редакторе

Подойдёт Photoshop, Affinity Photo, GIMP или другой редактор с масками слоёв и экспортом альфа-канала. Названия команд отличаются, но последовательность одинакова.

1. Сохраните оригинал и создайте рабочий многослойный файл. Для веб-экспорта используйте согласованный процесс работы в sRGB.
2. Создайте копии композиции для фона, объекта и переднего плана.
3. Выделите главный объект. Для жёсткого контура используйте точный путь; для атмосферных деталей — уточнённую мягкую маску. Применяйте маску слоя, сохраняя возможность исправить исходные пиксели.
4. Удалите из маски все отверстия и пустые пространства внутри объекта. Посмотрите результат в масштабе 100% и 200% на белом, тёмно-фиолетовом, оранжевом и контрастном фоне.
5. Восстановите части объекта, которые были скрыты облаками или ландшафтом. Дорисуйте, отрендерите или сгенерируйте их. Одна маска не может восстановить пиксели, которых нет в исходнике.
6. На копии фона полностью удалите главный объект и те элементы переднего плана, которые станут отдельными слоями. Заполните освободившиеся области правдоподобным небом или ландшафтом. Продолжите линии горизонта, освещение и фактуру. Не должно остаться «призрака» объекта.
7. Выделите передний план. Сохраните частичную прозрачность по краям облаков и пены. Не оставляйте прямоугольную границу или резкий нижний срез, который появится при смещении.
8. Соберите полученные слои поверх чистого фона и сравните с утверждённой композицией. Согласуйте цвет, экспозицию, резкость, зерно и локальный контраст.
9. Имитируйте будущую анимацию прямо в редакторе: переместите объект вверх и вбок, уменьшите его, сдвиньте передний план. Осмотрите все открывшиеся участки.
10. Экспортируйте каждый слой отдельно. Сохраните редактируемый оригинал, маски и запросы генерации.

### 5.3 Стекло, отражения и мягкие края

PNG со стеклом остаётся плоским изображением. Оно не будет физически правильно преломлять произвольный новый фон как настоящий 3D-объект. Используйте стекло, оттенки и отражения которого уже соответствуют сцене. Альфа-канал делает прозрачными окружение и открытые отверстия, но сам по себе не создаёт правильное преломление внутри материала.

Следите за светлой каймой после вырезания объекта с белого фона. Исправляйте цвет края, а не уменьшайте маску до исчезновения мелких деталей. Не применяйте сильное размытие маски к чёткому металлическому контуру. Облаку нужна мягкая прозрачность; хрому — точный край с естественным сглаживанием.

Сгенерированная картинка с шахматным узором — это иногда непрозрачное изображение шахматного узора. Проверяйте реальный альфа-канал. Серый или белый прямоугольник вокруг объекта не является прозрачностью.

### 5.4 Размер холста и обрезка

Есть два корректных подхода: все слои на общем холсте с совпадающими координатами или отдельно обрезанные объекты с позиционированием в CSS. В MOTION используются широкие фоны, квадратные главные объекты и отдельные холсты переднего плана. За их расположение отвечает CSS. Нельзя ожидать, что они автоматически совпадут при `left: 0; top: 0`.

Оставляйте около 5–10% прозрачного поля вокруг квадратного объекта, чтобы его силуэт не был обрезан. Учитывайте эти поля: слишком много пустоты сделает объект визуально маленьким даже при большом CSS-размере. У фона должно быть достаточно полезного изображения за пределами видимого кадра, чтобы камера могла смещаться и менять масштаб.

**Контрольная точка:** статичная композиция должна убедительно выглядеть и в широком, и в вертикальном кадре до начала анимации.

<a id="s06"></a>
## 6. Как писать запросы для генерации изображений

Отдельно описывайте тип результата, композицию, материал, свет, палитру, свободную область для текста и требования к прозрачности. Для извлечения объекта передавайте утверждённую сцену как изображение-референс. Только текстовый запрос может дать другое кольцо или другой ракурс.

Пример задания для нового фона:

```text
Создай широкую фотографичную фоновую подложку для многослойного сайта.
Лавандовое небо, персиковый закатный свет сверху справа, далёкое спокойное море.
Левые 40% оставь спокойными для крупного заголовка. Основные детали справа.
```

## 7. Как экспортировать, проверять и оптимизировать графику

### 7.1 Реальные изображения проекта

Параметры прочитаны из текущих файлов. КиБ — это 1024 байта. Эти размеры служат примером, а не обязательным стандартом для любого сайта.

| Файл в `public/images` | Размер в пикселях | Альфа-канал | Примерный размер, КиБ |
| --- | --- | --- | --- |
| `cloud-background.webp` | 1672 × 941 | Нет | 169 |
| `chrome-orbit.webp` | 1254 × 1254 | Есть | 324 |
| `cloud-foreground.webp` | 1774 × 887 | Есть | 301 |
| `desert-background.webp` | 1672 × 941 | Нет | 86 |
| `moon.webp` | 1254 × 1254 | Есть | 345 |
| `ocean-background.webp` | 1672 × 941 | Нет | 152 |
| `glass-knot.webp` | 1254 × 1254 | Есть | 320 |
| `ocean-foreground.webp` | 1672 × 941 | Есть | 222 |

Всего около 1,96 МБ в десятичной системе, или 1,87 МиБ. После декодирования изображения занимают значительно больше памяти, чем их сжатые файлы.

### 7.2 Порядок экспорта

1. Сохраните соответствующие восемь `.png` в `artwork/` с теми же именами без расширения.
2. Сохраните прозрачность объектов и переднего плана. Не объединяйте их с белой подложкой.
3. Из корня проекта выполните:

```sh
node scripts/prepare-assets.mjs
```

Скрипт перезапишет соответствующие WebP в `public/images`. Основная операция:

```js
await sharp(`artwork/${name}.png`)
  .webp({ quality: 88, alphaQuality: 100, effort: 6 })
  .toFile(`public/images/${name}.webp`);
```

Это настройки конкретного проекта, а не универсально лучшие значения. Проверяйте края и плавные градиенты после экспорта. `quality: 88` означает сжатие цвета с потерями; RGB-пиксели не будут полностью идентичны исходнику. Параметры описаны в [документации Sharp по WebP](https://sharp.pixelplumbing.com/api-output/#webp).

Текущий скрипт не меняет размеры, не корректирует цвет, не удаляет фон, не создаёт маски и не обновляет JSON происхождения. Эти действия выполняются отдельно. Приводите запрос и сведения об исходнике в каждом `.webp.json` в соответствие с новым изображением.

### 7.3 Проверка настоящей прозрачности

Необязательная диагностика: сохраните код как `scripts/check-alpha.mjs` и выполните `node scripts/check-alpha.mjs`. Он читает изображения, не изменяя их:

```js
import sharp from 'sharp';

for (const name of ['chrome-orbit', 'moon', 'glass-knot',
                    'cloud-foreground', 'ocean-foreground']) {
  const file = `public/images/${name}.webp`;
  const metadata = await sharp(file).metadata();
  if (!metadata.hasAlpha) throw new Error(`${name}: no alpha channel`);
  const { data } = await sharp(file)
    .extractChannel('alpha').raw().toBuffer({ resolveWithObject: true });
  let min = 255, max = 0, partial = 0;
  for (const value of data) {
    min = Math.min(min, value);
    max = Math.max(max, value);
    if (value > 0 && value < 255) partial++;
  }
  console.log(name, { min, max, partial });
  if (min === 255) throw new Error(`${name}: alpha is completely opaque`);
}
```

Значения альфа-канала доказывают, что прозрачность где-то существует, но не подтверждают правильность всей маски. Всё равно осмотрите отверстие кольца, края и восстановленные участки.

### 7.4 Как выбрать разрешение

Оцените максимальный размер объекта в CSS-пикселях, умножьте на целевую плотность пикселей устройства и на наибольший масштаб, при котором объект заметно присутствует в кадре. Сравните с разрешением исходника. Картинка 1254 пикселя, показанная размером 900 CSS-пикселей, не даст полноценной резкости 2×. Решите, приемлем ли этот компромисс на конкретном изображении.

Для более крупного проекта подготовьте несколько разрешений и используйте `srcSet`/`sizes`. Сохраняйте пропорции и одинаковые прозрачные поля у вариантов. Для телефона иногда нужен другой художественный кадр, а не просто уменьшенная копия. Сейчас проект использует одно разрешение каждого слоя; набор адаптивных изображений — возможное расширение.

## 8. Как сначала собрать статичную композицию

Ниже структура внутри компонента. Полные текст и управление находятся в [Worlds.jsx](../src/Worlds.jsx):

```jsx
<div className="world-backdrop cloud-backdrop motion-layer">
  <img className="world-camera" src="/images/cloud-background.webp" alt="" />
</div>

<section className="world world-cloud" aria-labelledby="hero-title">
  <div className="world-object orbit-object motion-layer" aria-hidden="true">
    <img src="/images/chrome-orbit.webp" alt="" />
  </div>
  <div className="cloud-foreground motion-layer" aria-hidden="true">
    <img src="/images/cloud-foreground.webp" alt="" />
  </div>
  <div className="world-scrim cloud-scrim motion-layer" />
  <div className="world-copy">
    <h1 id="hero-title">Ideas beyond ordinary.</h1>
  </div>
</section>
```

Сначала расположите одну сцену без классов анимации. Настройте базовые размеры и положение:

```css
.world, .world-backdrops, .world-scrim { position: absolute; inset: 0; }
.world-backdrops { z-index: -3; }
.world-backdrop { position: absolute; inset: 0; width: 100%; height: 100%; }
.world-camera { display: block; width: 100%; height: 100%; object-fit: cover; }
.world-object { position: absolute; pointer-events: none; }
.world-object img { width: 100%; height: 100%; object-fit: contain; }
.orbit-object {
  width: min(60vw, 88svh);
  height: min(60vw, 88svh);
  right: 3vw;
  top: 5svh;
}
```

`cover` заполняет кадр фоном, обрезая изображение при несовпадении пропорций. `contain` сохраняет весь холст объекта внутри его блока. Облако или волна располагаются отдельно. У текущей волны используется `object-fit: fill`: это осознанное растяжение для данной композиции. Не переносите его автоматически на лицо или узнаваемую техническую форму.

Оставляйте текст HTML-текстом, не рисуйте его внутри изображений. Используйте настоящие заголовки и ссылки. В проекте применены Manrope, светлый `#fffaf5`, персиковый `#f3bbae`, сливовый `#282331` и боковой отступ `clamp(24px, 5.5vw, 96px)`. Учитывайте лицензию шрифта из `public/fonts/OFL.txt`.

Затемнение состоит из градиента слева и более сильного градиента снизу. Оно поддерживает контраст текста при движении графики. Проверяйте читаемость на обоих концах траектории фоновой камеры, а не только в первом кадре.

## 9. Как устроить закреплённую сцену и координату скролла

```css
.worlds-scroll {
  height: 580svh;
  position: relative;
  view-timeline-name: --worlds;
  view-timeline-axis: block;
  view-timeline-inset: 0;
}
.worlds-stage {
  height: 100svh;
  position: sticky;
  top: 0;
  overflow: clip;
  isolation: isolate;
}
```

Высокий внешний контейнер создаёт расстояние прокрутки. Внутренний кадр остаётся закреплённым, пока это расстояние проходит мимо него. Все сцены занимают одну область экрана и не выталкивают друг друга вниз.

Обозначим высоту истории `H`, фактическую высоту кадра `V`, а начало истории в документе `S`. Доступный путь: `D = H − V`. Нормализованный прогресс и координата сцены:

```text
p = clamp((scrollY − S) / D, 0, 1)
targetY = S + D × sceneProgress
```

В проекте `getBoundingClientRect().top` даёт `S − scrollY`, поэтому запасной расчёт использует `clamp(-rect.top / travel, 0, 1)`.

Например, при высоте кадра 900 пикселей контейнер 580svh создаёт путь 4320 пикселей. Остановки 0, .44 и .94 находятся на 0, 1900,8 и 4060,8 пикселя относительно начала истории. Эти числа иллюстративны: в коде нужно измерять DOM, а не жёстко записывать рассчитанные пиксели.

`svh` задаёт стабильную высоту малого видимого окна, что полезно при появлении панелей мобильного браузера. Код считывает реальную высоту кадра, чтобы расчёт прокрутки совпадал с CSS. На мобильных высота истории меняется на `520svh`.

`view-timeline-inset: 0` нужен явно: на странице есть отступ прокрутки для шапки, а неявные отступы временной шкалы могут сдвинуть ожидаемый прогресс. Не создавайте случайно новый прокручиваемый контейнер у предка: это может изменить поведение `position: sticky`.

## 10. Как связать CSS со скроллом и сделать запасной вариант

Сначала задаётся запасной механизм. Остановленная анимация длиной одну секунду с отрицательной задержкой показывает выбранное место в ключевых кадрах:

```css
.motion-layer {
  animation-name: var(--motion);
  animation-duration: 1s;
  animation-timing-function: linear;
  animation-fill-mode: both;
  animation-play-state: paused;
  animation-delay: calc(var(--scroll-p, 0) * -1s);
}
@supports (animation-timeline: view()) and
          (animation-range: contain 0% contain 100%) {
  .motion-layer {
    animation-duration: auto;
    animation-delay: 0s;
    animation-play-state: running;
    animation-timeline: --worlds;
    animation-range: contain 0% contain 100%;
  }
}
```

Для контейнера истории, который выше экрана, диапазон `contain` соответствует времени, пока контейнер покрывает видимое окно. Шкала отображает этот интервал на ключевые кадры. Размещайте `animation-timeline` после сокращённой записи `animation`, если используете её: сокращение может сбросить привязку. Семантика и актуальная совместимость описаны в [справочнике animation-timeline](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timeline).

В [App.jsx](../src/App.jsx) проверяются те же две возможности через `CSS.supports`. Если поддержки нет, события scroll/resize обновляют `--scroll-p`, причём записи объединяются через один `requestAnimationFrame`. Таким образом используются те же ключевые кадры и те же положения сцены.

```js
const travel = Math.max(1, story.offsetHeight - stage.offsetHeight);
const p = Math.max(0, Math.min(1, -story.getBoundingClientRect().top / travel));
story.style.setProperty('--scroll-p', p.toFixed(5));
```

Этот фрагмент относится к запасной ветке. Не запускайте его как конкурирующую систему управления поверх нативной шкалы. Не обновляйте состояние React на каждый пиксель: непрерывные значения записывайте в CSS-переменные, а состояние меняйте при смене активной сцены.

CSS-шкала линейна относительно скролла. Сам контроллер навигации уже изменяет скролл с плавным ускорением и замедлением. Дополнительное общее сглаживание всех ключевых кадров изменит итоговую динамику и может сделать движение вязким.

## 11. Как поставить переходы между сценами

До записи CSS нарисуйте всю временную шкалу. Первый переход занимает её первую половину, второй повторяет ритм со сдвигом на 50 процентных пунктов. Остановки находятся в 0, .44 и .94 — внутри спокойных участков композиции, а не строго на математических границах половин.

| Дорожка | Первый переход | Второй переход |
| --- | --- | --- |
| Уходящий фон | Удерживается до 6%; исчезает к 34% | Удерживается до 56%; исчезает к 84% |
| Приходящий фон | Скрыт до 10,5%; установлен к 35% | Скрыт до 60,5%; установлен к 85% |
| Приходящий объект | Скрыт до 9%; занимает место к 38,5% | Скрыт до 59%; занимает место к 88,5% |
| Новый заголовок | Скрыт до 19,5%; установлен к 34% | Скрыт до 69,5%; установлен к 84% |
| Новое описание | Скрыто до 26%; установлено к 40% | Скрыто до 76%; установлено к 90% |
| Смена активной сцены | 25% | 75% |

Проценты здесь — координаты прогресса, не секунды. Каждое действие навигации по-прежнему длится 1,8 секунды; расстояния между остановками в пикселях не одинаковы.

Пример ухода кольца из текущего проекта:

```css
.orbit-object { --motion: orbit-out; }
@keyframes orbit-out {
  0% { transform: translate3d(0, 0, 0) rotate(0deg) scale(1); opacity: 1; }
  7.5% { transform: translate3d(-1vw, -3svh, 0) rotate(-3deg) scale(1.02); opacity: 1; }
  24% { transform: translate3d(9vw, -47svh, 0) rotate(-24deg) scale(.9); opacity: 1; }
  34%, 100% { transform: translate3d(16vw, -110svh, 0) rotate(-40deg) scale(.72); opacity: 0; }
}
```

Начальное смещение подчёркивает глубину, средняя часть выводит объект за кадр, а невидимый конечный участок не позволяет ему появиться снова. Следующий объект поднимается снизу с собственными поворотом и масштабом. Передний план перемещается иначе: поэтому сцена воспринимается пространственной, а не одной плоской карточкой.

Используйте отдельные дорожки для фонов, объектов, переднего плана, строк заголовка, описаний, подписей и индикатора прогресса. Сначала настройте перемещение и прозрачность. Затем добавьте ограниченные поворот, масштаб и небольшое размытие на переходе. Сильное размытие огромного фона может дорого обходиться браузеру и скрывать плохую постановку вместо её исправления.

Для строк заголовка используется `--line`, изменяющая расстояние перемещения:

```jsx
<span className="story-line motion-layer"
      data-line={index} style={{ '--line': index }}>{word}</span>
```

```css
transform: translate3d(0, calc(-42svh - var(--line) * 9svh), 0);
```

Разная дистанция создаёт расхождение строк без набора несвязанных таймеров. Если визуально делите заголовок на части, сохраняйте его полную доступную подпись.

Проверяйте середину перехода, а не только конечные кадры. Новый фон должен достаточно перекрывать сцену до исчезновения старого. Затемнения должны поддерживать читаемость. Пройдите ту же шкалу в обратном направлении: обратному скроллу не нужен отдельный набор анимаций появления.

## 12. Как объединить скролл и кнопки одним контроллером

Используйте полный [sceneNavigation.js](../src/sceneNavigation.js), а не независимые вызовы `scrollIntoView` с приблизительно подобранными задержками.

Контроллер получает окно, документ, описание сцен, настройку уменьшения движения и функцию получения актуального состояния меню. Он возвращает `navigate(id, instant)` и `destroy()`.

```js
export const SCENE_MOTION = {
  duration: 1800,
  pause: 0,
  gestureGap: 180,
  threshold: 32,
};
const ease = t => t * t * t * (t * (t * 6 - 15) + 10);
```

`ease` — плавная функция пятой степени: движение ускоряется и замедляется у концов. Каждый кадр рассчитывается так:

```text
t = min(1, прошедшееВремя / 1800)
scrollY = startY + (targetY − startY) × ease(t)
```

Внутри кадров используется `scrollTo({ top, behavior: 'instant' })`. Плавностью уже управляет контроллер, поэтому браузер не должен запускать вторую smooth-анимацию на каждом обновлении. Целевая координата определяется геометрией истории. Если во время перехода изменяется размер окна, переход сразу завершается в предусмотренной точке назначения.

Все способы ввода вызывают этот контроллер. Ссылка сохраняет осмысленный `href`, но обработчик React отменяет стандартный переход и вызывает `goTo(id)`. Нумерованные кнопки и стрелка вызывают ту же функцию. Контроллер обновляет фрагмент URL через `history.replaceState`, поэтому каждый шаг не добавляет запись в историю браузера.

React создаёт элементы позже первоначального поиска фрагмента браузером. Эффект при монтировании в `App.jsx` восстанавливает корректный начальный hash после появления элементов, используя тот же расчёт назначения. Проверяйте прямое открытие `/#afterglow`, а не только переход с первого слайда.

Создавайте контроллер в эффекте и вызывайте `destroy()` при очистке. Это предотвращает дублирование обработчиков в React Strict Mode и при изменении настройки уменьшения движения. Актуальное состояние меню считывайте через ref, чтобы не пересоздавать контроллер на каждом рендере.

<a id="s13"></a>
## 13. Как ограничить частые события и инерцию трекпада

Debounce ждёт прекращения событий, прежде чем выполнить действие. Здесь нужен немедленный ответ на первый жест и отбрасывание лишнего ввода во время перехода: throttle с немедленным первым действием и распознаванием границ жеста.

Алгоритм текущего проекта:

1. Привести `wheel`-дельты к приблизительным пикселям: пиксельный режим ×1, строковый ×16, страничный ×высоту окна.
2. Пропустить сочетания для масштабирования, преимущественно горизонтальное движение и ввод в редактируемых полях.
3. Перехватывать событие только там, где последовательность сцен управляет данным направлением; ниже истории скролл обычный.
4. Накопить небольшие вертикальные дельты до порога 32.
5. Начать один переход и отметить текущий жест как использованный.
6. Отбрасывать последующие события во время перехода. Не ставить следующий слайд в очередь.
7. Считать жест новым после промежутка не менее 180 мс между событиями колеса.

**Фиксированной паузы после анимации нет.** `pause: 0` сразу снимает блокировку перехода. Интервал тишины 180 мс — другая защита: он не даёт инерционному хвосту того же жеста трекпада запустить новый слайд. Новое нажатие кнопки может сработать сразу после завершения; хвост старого wheel-жеста — нет.

Обнуление `pause` не означает, что любое непрерывное колесо должно листать сцены подряд. Без блокировки использованного жеста один длинный бросок трекпада пропустит всю историю.

На сенсорном экране используется порог вертикального движения одним пальцем; каждый жест расходуется один раз. Масштабирование двумя пальцами и горизонтальные жесты остаются браузеру. Клавиатурная навигация игнорирует автоповтор зажатой клавиши, редактируемые поля и Space на элементах, которым нужен собственный запуск. Стрелки и Page Up/Down используют общий контроллер.

Слушатели wheel/touchmove, вызывающие `preventDefault()`, регистрируются с `{ passive: false }`. Не ставьте `touch-action: none` на всю страницу и не отменяйте глобально все wheel-события. Контроллер отдаёт ввод браузеру за границами истории и поддерживает обратный шаг из студии к последней сцене.

<a id="s14"></a>
## 14. Как добавить параллакс от курсора

Нормализуйте положение курсора относительно кадра:

```text
x = clamp(2 × (clientX − stageLeft) / stageWidth − 1, −1, 1)
y = clamp(2 × (clientY − stageTop) / stageHeight − 1, −1, 1)
```

В центре получится `(0, 0)`, на правом краю — `x = 1`. Храните последнее положение мыши, планируйте не более одного `requestAnimationFrame` и записывайте `--pointer-x` и `--pointer-y` на контейнер сцены. Не запускайте рендер React на каждое движение указателя.

Полный обработчик и очистка находятся в `Worlds.jsx`. Принимается именно мышь при поддержке точного указателя и наведения. Эффект отключается при уменьшении движения, открытом меню и переходе к разделам после истории. Уход указателя из окна, потеря фокуса окна, изменение размеров и скрытие документа сбрасывают смещение.

```css
.world-object img {
  transform:
    translate3d(
      calc(var(--pointer-x, 0) * var(--pointer-travel-x)),
      calc(var(--pointer-y, 0) * var(--pointer-travel-y)), 0)
    rotate(calc(var(--pointer-x, 0) * var(--pointer-turn)));
  transition: transform 700ms cubic-bezier(.16, 1, .3, 1);
}
.orbit-object {
  --pointer-travel-x: 16px;
  --pointer-travel-y: 11px;
  --pointer-turn: .8deg;
}
```

У планеты значения 10px/8px/.25deg, у стеклянной скульптуры — 18px/12px/1deg. Разная амплитуда создаёт разное ощущение массы. Переход 700 мс смягчает реакцию при смене целевого положения; это не ожидание 700 мс перед началом движения.

Оставляйте transform от скролла на `.world-object`, а transform от курсора — на дочернем `img`. Чтобы изменить направление воспринимаемой глубины, можно поменять знак амплитуды, но затем проверить все сцены. Слишком сильное смещение может завести объект на заголовок или открыть нежелательную область обрезки.

<a id="s15"></a>
## 15. Как сделать самостоятельное движение фона

Внешний контейнер фона отвечает за перемещение и прозрачность при скролле. Дочернее изображение имеет обычную медленную CSS-анимацию: она продолжает идти, когда пользователь не прокручивает страницу.

```css
.world-camera {
  display: block;
  width: 100%; height: 100%; object-fit: cover;
  animation: var(--camera-path) var(--camera-duration)
             ease-in-out infinite alternate both;
  animation-play-state: paused;
}
.worlds-stage[data-camera-enabled="true"][data-camera-visible="true"]
.world-camera { animation-play-state: running; }

.cloud-backdrop { --camera-path: cloud-camera; --camera-duration: 18s; }
@keyframes cloud-camera {
  from { transform: translate3d(-1%, .6%, 0) scale(1.16); }
  to   { transform: translate3d(1%, -.6%, 0) scale(1.06); }
}
```

| Сцена | Начальное положение | Конечное положение | Время в одну сторону |
| --- | --- | --- | --- |
| Облака | x −1%, y +.6%, масштаб 1.16 | x +1%, y −.6%, масштаб 1.06 | 18 с |
| Пустыня | x +1.4%, y −.4%, масштаб 1.07 | x −1.4%, y +.6%, масштаб 1.15 | 22 с |
| Море | x −1.2%, y +.7%, масштаб 1.08 | x +1.2%, y −.7%, масштаб 1.14 | 20 с |

`alternate` возвращает движение назад, а не резко перескакивает к первому кадру. Полный цикл туда и обратно занимает 36, 44 или 40 секунд. `ease-in-out` замедляет развороты. Эти длительности никак не заменяют переход между слайдами в 1,8 секунды.

Не пересоздавайте изображения камер при смене активной сцены и не меняйте имя их анимации на каждом переходе. Три фона остаются смонтированными; их фазы продолжаются, пока история включена, даже если отдельный слой сейчас прозрачен. Это позволяет возвращаться назад и выполнять смешивание без сброса фонового движения. Для большого количества сцен потребуется отдельное управление видимостью слоёв с сохранением фазы.

В `Worlds.jsx` используются `IntersectionObserver` и `visibilitychange`, задающие `data-camera-visible`. React устанавливает `data-camera-enabled` по состоянию сцены, меню и уменьшения движения. Вместе они ставят камеры на паузу вне истории, за меню и в скрытой вкладке. CSS уменьшения движения удаляет анимацию полностью. Наблюдатель и обработчики обязательно очищаются.

### Как не показать края картинки

Если изображение изначально заполняет родителя и масштабируется относительно центра, масштаб `s` даёт примерно `(s − 1) / 2` дополнительной ширины с каждой стороны относительно исходной ширины. При `s = 1.06` это 3% на сторону. Горизонтальное смещение 1,4% помещается в такой запас. Вертикальную ось нужно проверить отдельно.

Этот расчёт относится к показанному порядку `translate3d(...) scale(...)` без поворота. Другой порядок трансформаций, поворот, изменённый центр или изображение меньше родителя меняют геометрию. Внешняя scroll-анимация тоже трансформирует фон, поэтому осматривайте не только крайние положения камеры, но и переходы между сценами. Обрезайте изображение границами кадра и не рассчитывайте скрыть пробел цветом страницы.

<a id="s16"></a>
## 16. Как адаптировать композицию под телефон и низкий экран

Вертикальному экрану нужна новая композиция, а не только уменьшенные размеры настольной версии.

1. Сохраните читаемый размер заголовка и отступ текста.
2. Разрешите главному объекту осознанно выходить за правый край, оставляя узнаваемую центральную часть.
3. Смещайте `object-position` фона к важной области. В проекте ниже 680px используется `62% center`.
4. Перенесите описание вниз влево и оставьте место навигации и подписи.
5. Скрывайте длинные названия пагинации, сохраняя номера кнопок и доступные подписи.
6. После изменения размеров переднего плана проверьте его края.

Текущий пример композиции кольца на телефоне:

```css
@media (max-width: 680px) {
  .worlds-scroll { height: 520svh; }
  .orbit-object { width: 115vw; height: 115vw; right: -32vw; top: 12svh; }
  .world-camera { object-position: 62% center; }
  .pagination-name { display: none; }
}
```

В проекте также есть промежуточная точка 1000px и отдельные правила при высоте меньше 650px. Проверяйте телефон в альбомной ориентации и низкое окно настольного браузера. Крупный текст может столкнуться с управлением даже при достаточной ширине.

Полезный набор ширин для проверки: 320, 390, 768, 1024 и 1440 CSS-пикселей, дополненный реальными устройствами. Убедитесь, что ширина документа не превышает окно. Увеличенные изображения должны обрезаться внутри сцены, не создавая горизонтальную прокрутку страницы. На сенсорном устройстве параллакса от мыши нет; самостоятельное движение фона может сохраняться, если пользователь не запросил уменьшение движения.

<a id="s17"></a>
## 17. Где применять современные возможности CSS

| Возможность | Задача в этом проекте | Запасной вариант |
| --- | --- | --- |
| `animation-timeline` и `animation-range` | Связать положение истории с ключевыми кадрами | Остановленная анимация с отрицательной задержкой |
| Типизированный `attr()` | Читать индекс строки из `data-line` | Inline-переменная `--line` |
| `interpolate-size: allow-keywords` | Улучшить раскрытие блоков услуг по высоте | Стандартное открытие/закрытие |
| `calc-size()` | Для текущих эффектов не требуется | Не добавлять без задачи вычисления размера |

`allow-keywords` — значение свойства `interpolate-size`, а не отдельное свойство. Улучшение раскрытия ограничено `.services`, проверяет поддержку свойства и `details::details-content`, затем анимирует высоту от нуля до `auto`. За кинематографичные переходы сцен оно не отвечает. Подробнее: [interpolate-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/interpolate-size).

Типизированный `attr()` подключается с проверкой:

```css
@supports (z-index: attr(data-line type(<number>), 0)) {
  .story-line { --line: attr(data-line type(<number>), 0); }
}
```

Текущий компонент также задаёт `--line` inline. Такое объявление побеждает в каскаде, поэтому числовое значение работает независимо от поддержки типизированного `attr()`. Если хотите сделать атрибут настоящим источником значения, удаляйте inline-переменную только после подготовки и проверки другого запасного механизма. Подробнее: [attr()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/attr).

`calc-size()` нужен для вычислений с внутренними размерами содержимого. Он сам по себе не улучшает `transform` и не делает движение плавнее только потому, что появился в таблице стилей. Применяйте его при реальной задаче арифметики с такими размерами. Подробнее: [calc-size()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/calc-size).

Не стройте архитектуру на неизменных списках версий браузеров. Проверяйте возможности и фактическое отображение в целевых браузерах: успешный `@supports` ещё не доказывает правильность всей сцены.

## 18. Доступность и управление движением

Режим уменьшения движения в проекте — отдельная читаемая компоновка:

- Убирается высота закреплённой истории, три секции идут в обычном потоке документа.
- Удаляются трансформации сцен и самостоятельное движение фона.
- Каждая секция получает собственный статичный фон.
- Содержимое всех сцен остаётся доступным; статичные сцены не становятся inert.
- Перехват ввода отключается, навигация ведёт непосредственно к статичным секциям.
- Убирается управление временной шкалой, но сохраняется полезная навигация по странице.

В анимированном режиме неактивные сцены получают `inert`, поэтому невидимые ссылки не попадают в последовательность Tab. Декоративные изображения имеют пустой `alt`, а их контейнеры скрыты от вспомогательных технологий. Смысловой текст остаётся в HTML. Используйте один основной H1, H2 разделов, подписи кнопок, заметный фокус и `aria-current`.

Следите за изменением настройки через `matchMedia(...).addEventListener('change', ...)`, а не только при открытии страницы. Контроллер должен пересоздаваться с новым режимом, а старые эффекты — корректно завершаться.

Для публичной версии с бесконечным самостоятельным движением добавьте видимую кнопку «Остановить движение / Продолжить движение» и учитывайте её состояние в `data-camera-enabled`. В текущем концепте есть автоматическая пауза и поддержка системного уменьшения движения, но **нет отдельной кнопки паузы на странице**. На этом основании нельзя заявлять полное соответствие требованиям доступности. [Разъяснение W3C Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) описывает управление подходящим под критерий автоматическим движением дольше пяти секунд рядом с другим содержимым.

Также проверьте всю страницу с клавиатуры, увеличенный текст, контраст поверх движущегося фона и размеры сенсорных целей. Если изображение передаёт существенную информацию, а не только атмосферу, дайте ему подходящую текстовую альтернативу.

<a id="s19"></a>
## 19. Производительность и загрузка

Оптимизируйте в таком порядке: размеры и сжатие изображений, количество декодированных слоёв, стоимость отрисовки, затем накладные расходы JavaScript.

1. Быстро загружайте первый фон. `index.html` предварительно загружает его, а первый фон и объект имеют высокий fetch priority. Не объявляйте одинаково приоритетными все ресурсы.
2. Подготавливайте следующую сцену до перехода к ней. Сейчас все три сцены смонтированы без lazy loading. В более длинной истории заранее загрузите и декодируйте соседнюю сцену и предусмотрите понятное состояние загрузки вместо пустого перехода.
3. Для больших слоёв предпочитайте transform и opacity. Измеряйте стоимость размытия: огромная движущаяся размытая подложка может требовать дорогой отрисовки.
4. Не храните непрерывные координаты курсора и прогресса в состоянии React. Объединяйте чтения и записи по кадрам, удаляйте обработчики при очистке.
5. Останавливайте фоновую анимацию в скрытом документе и вне истории. Для CSS-камеры не нужен бесконечный JavaScript-цикл.
6. Добавляйте `will-change` только по результатам измерений. Постоянное выделение отдельных поверхностей для всех больших изображений увеличивает расход памяти.

Грубая оценка несжатого RGBA: `ширина × высота × 4` байта. Изображение 1672×941 занимает примерно 6 МиБ по такой оценке; 1254×1254 — тоже около 6 МиБ. Восемь файлов общим весом меньше 2 МБ после декодирования могут занимать десятки мегабайт, а дополнительные поверхности композитора увеличивают расход дальше.

Используйте панели Performance и Network на реальном целевом устройстве. Смотрите пропущенные кадры, длинные задачи, задержки декодирования, перерисовку и память. Успешная сборка подтверждает сборку приложения, но не стабильные 60 fps. Для проекта не заявлена измеренная гарантия частоты кадров на всех устройствах.

## 20. Проверка и поиск ошибок

### 20.1 Уже имеющиеся автоматические проверки

```sh
npm run build
node scripts/scene-navigation.test.mjs
```

Восемь тестов проверяют сильные wheel-серии, одинаковую траекторию кнопки и колеса, ввод во время блокировки, инерцию трекпада, малые дельты, границы студии, уменьшение движения/модификаторы/поля и touch/очистку. Они проверяют логику навигации в управляемом окружении. Они не отрисовывают CSS, не оценивают маски и не измеряют производительность устройства.

### 20.2 Ручная проверка по шагам

1. Откройте первую сцену и не двигайте мышью: фон должен медленно двигаться самостоятельно.
2. Переместите курсор по углам: объект слегка реагирует, текст остаётся стабильным.
3. Выполните один жест колеса, затем длинную быструю серию: каждый жест должен давать только один переход.
4. Используйте стрелку и номера: длительность и назначение совпадают с колесом.
5. Пройдите все сцены назад. Осмотрите середину каждого перехода: нет ли пустых областей, двойных силуэтов, резкого сброса.
6. Останьтесь в каждой сцене на полный цикл камеры и проверьте разворот и края.
7. Перейдите в студию: фоновые анимации ставятся на паузу, скролл вниз становится обычным.
8. Проверьте свайп, масштабирование двумя пальцами, горизонтальный жест, клавиатуру, открытое меню и ввод в форму.
9. Перезагрузите страницу с каждым фрагментом сцены; измените размер окна во время перехода.
10. Проверьте уменьшение движения и вариант без нативной scroll timeline. Проверьте навигацию по статичным секциям.
11. Проверьте медленную загрузку, ошибку получения картинки, узкое окно и низкий экран в альбомной ориентации.

Полезная диагностика только для чтения в консоли браузера:

```js
[...document.querySelectorAll('.world-camera')].map(image => ({
  loaded: image.complete && image.naturalWidth > 0,
  transform: getComputedStyle(image).transform,
  playState: getComputedStyle(image).animationPlayState,
  opacity: getComputedStyle(image.parentElement).opacity,
}));
document.documentElement.scrollWidth > window.innerWidth;
```

Сравните transform камеры с интервалом в несколько секунд, не прокручивая страницу. Отдельно проверьте transform родителя, чтобы подтвердить независимость механизмов. Запасной режим тестируйте в контролируемом варианте для разработки или браузере без соответствующей поддержки. Одного изменения JavaScript-проверки недостаточно, если нативная CSS-ветка `@supports` продолжает работать.

### 20.3 Таблица диагностики

| Симптом | Вероятная причина | Что сделать |
| --- | --- | --- |
| Прямоугольник вокруг объекта | Нет настоящего alpha или экспорт объединён с фоном | Проверить метаданные и наложить на контрастные цвета |
| В отверстии кольца осталось старое небо | Внутренняя область не вырезана | Исправить alpha отверстия и экспортировать заново |
| Светлая кайма | Край загрязнён цветом старого фона | Исправить цвет/маску края и проверить в реальном размере |
| Сзади виден второй объект | Главный объект остался на фоновой подложке | Полностью восстановить чистый фон |
| При уходе появляется плоский срез | Скрытая часть объекта не восстановлена | Дорисовать полноценный силуэт |
| Фон прыгает в конце цикла | Повторяется `from → to` без возврата | Использовать согласованные концы или `alternate` |
| Движение камеры пропадает при скролле | Обе системы пишут один transform | Разделить внешний контейнер и внутреннее изображение |
| Первая сцена слишком рано исчезает | Ошибочный range/inset или влияние scroll padding | Проверить путь прокрутки и явный inset |
| Трекпад пропускает несколько сцен | Ввод ставится в очередь или инерция считается новым жестом | Восстановить блокировку, использованный жест и quiet gap |
| Появляется край фона | Недостаточный запас масштаба или неверный центр | Пересчитать запас и проверить крайние положения |
| Фокус попадает на невидимые ссылки | Скрытие сделано только opacity | Применить `inert` к неактивной анимированной сцене |
| В статичном режиме пропали сцены | Остались inert или sticky-правила | Реализовать весь вариант уменьшения движения |
| Навигация реагирует с задержкой | До первого действия используется debounce | Запускать сразу, лишние события отбрасывать |
| Прямой URL открывает не то место | React-цели не было при первом поиске фрагмента | Восстановить hash после монтирования общим контроллером |
| Слои выглядят вклеенными | Не совпадают свет, зерно, ракурс или материал | Исправить графику до настройки анимации |
| Портретная страница шире окна | Размеры текста/объекта вышли за обрезающий контейнер | Пересобрать мобильную композицию и проверить ширину документа |

<a id="s21"></a>
## 21. Замена изображений и добавление четвёртой сцены

### Заменить одну сцену без изменения архитектуры

Сначала сохраните роли и имена файлов. Подготовьте полный фон, главный объект и необязательный передний план. Согласуйте прозрачные поля и пропорции либо перенастройте CSS-размеры. Экспортируйте, перезагрузите, проверьте статичный кадр, затем крайние положения скролла и камеры. Обновите текст, смысл alt, запросы генерации и происхождение. Новый силуэт не обязательно подходит к старой траектории.

### Добавить четвёртую сцену

Текущий компонент вручную поставлен для трёх сцен. Одной дополнительной записи в массив недостаточно.

1. Добавьте исходники, WebP, запросы и имена в скрипт экспорта.
2. Добавьте описание сцены, якорь, разметку, траекторию камеры, фон статичного режима и текстовые дорожки.
3. Перераспределите временную шкалу. Для четырёх сцен три перехода могут занимать трети. При индексе перехода `i = 0, 1, 2` локальный прогресс `q` отображается как `p = (i + q) / 3`.
4. Пересчитайте ключевые кадры под новые интервалы. Если шаблоном служит текущий первый переход 0–50%, сначала получите локальную координату: `q = oldPercent / 50`. Нельзя просто дописать кадры за пределами 100%.
5. Выберите остановки внутри спокойных участков, пересчитайте якоря и высоту истории, чтобы сохранить удобную дистанцию.
6. Замените жёстко заданные границы `.25/.75` в `App.jsx` новыми или расчётом из данных. Также измените фиксированные индексы студии и проекта `3` и `4`: в обобщённой версии они должны стать `scenes.length` и `scenes.length + 1`.
7. Обновите доли расположения якорей в статичном режиме, поведение next/previous, индикатор и тесты. Контроллер получает остановки из `scenes`, но CSS и определение активного раздела пока не полностью универсальны.
8. Повторно оцените память и загрузку. Для длинной истории полезна загрузка соседних сцен и пауза полностью скрытых слоёв с сохранением фазы.

Любая промежуточная сцена должна уметь и появляться, и уходить. Ей нужна сквозная дорожка. Анимация только появления не обеспечит корректный выход.

<a id="s22"></a>
## 22. Сборка и публикация

```sh
npm run build
npm run preview
```

Откройте адрес preview и повторите основные проверки навигации и изображений. На статический хостинг загружается содержимое `dist/`. Сервер разработки не является готовым продакшен-развёртыванием.

Текущие пути начинаются с `/images` и `/fonts`, то есть предполагают размещение в корне сайта. Для адреса вида `/portfolio/` нужно согласованно настроить базовый путь Vite и пути ресурсов. Изменение только одного из них может оставить жёстко заданные CSS/JS-ссылки на старое расположение.

Обновите title, description, favicon, метаданные и изображение для социальных превью, а также временное название бренда. Сохраняйте лицензионное уведомление шрифтов. Сборочные JS/CSS с хешем можно надолго кешировать как неизменяемые; файлам со стабильными именами в `public/images` нужна версия или подходящая очистка кеша после замены.

Текущая форма проверяет поля и **скачивает локальный текстовый файл**. Она не отправляет сообщение. Для рабочего контакта отдельно реализуйте сервер или сервис форм, серверную валидацию, защиту от злоупотреблений, состояния отправки/ошибки и подходящую информацию об обработке данных. Секретные ключи сервиса нельзя помещать в клиентский код.

Understand Anything и инструменты подготовки дизайна помогают разработчику, но не нужны посетителю. Для работы сайта достаточно собранных статических файлов. [Заметки об установке](understand-anything.md) описывают локальные инструменты автора отдельно.

## 23. Порядок реализации и критерии готовности

Следуйте этому порядку: каждая контрольная точка отделяет один класс ошибок от другого.

| Шаг | Работа | Условие перехода дальше |
| --- | --- | --- |
| 1 | Раскадровка, текст, палитра, свет | Сцены принадлежат одному визуальному миру |
| 2 | Фон, вырезанный объект, передний план | Нет двойных объектов, отсутствующих пикселей и ложной прозрачности |
| 3 | Статичный широкий и мобильный кадр | Текст читается, форма объекта и перекрытие убедительны |
| 4 | Sticky-контейнер и расчёт прогресса | Значения 0 и 1 достигаются в предусмотренных точках |
| 5 | Первый переход между двумя сценами | Прямое и обратное движение работают без пробелов |
| 6 | Третья сцена и сквозные дорожки | Второй переход повторяет задуманный ритм |
| 7 | Общий контроллер ввода | Кнопка и колесо имеют одинаковые длительность и назначение |
| 8 | Throttle, touch, клавиатура | Нет очереди пропусков; вне истории ввод остаётся обычным |
| 9 | Реакция на курсор | Смещение небольшое и плавное, transform не конфликтует |
| 10 | Фоновая камера | Медленное непрерывное движение, безопасные края, плавный разворот |
| 11 | Уменьшение движения и управление | Статичный контент полный, невидимые элементы не получают фокус |
| 12 | Сжатие и проверка сборки | Ресурсы доступны, тесты проходят, производительность приемлема |

Не настраивайте все параметры одновременно. Сначала ритм, затем расстояния, масштаб/поворот, расхождение текста и только потом амплитуду камеры. Сохраняйте заведомо удачный вариант изображений и постановки, чтобы легче находить причину визуальной регрессии.

### Словарь

**Чистая подложка / clean plate:** фон с удалённым объектом и восстановленными скрытыми областями. **Alpha / альфа-канал:** прозрачность каждого пикселя. **Маска:** редактируемая информация о видимости слоя. **Scrim:** подложка для контраста текста. **Overscan:** запас изображения за границами видимого кадра. **Параллакс:** различное видимое движение элементов на разной глубине. **Timeline:** соответствие между прогрессом и состояниями анимации. **Throttle:** ограничение принимаемых действий с отбрасыванием лишних событий. **Debounce:** откладывание действия до затихания ввода. **Inert:** отключение взаимодействия и фокуса для поддерева элементов. **Fallback:** запасная реализация на случай отсутствия возможности браузера.
